[ ] GOOGLE SIGN-IN — OAuth 2.0 Client IDs (3 needed)
    Required for: "Continue with Google" on AuthLanding + Login screens.

    Step 1: Go to https://console.cloud.google.com/apis/credentials
    Step 2: Click "Create Credentials" → "OAuth client ID" three times:

      (a) Application type: iOS
          Bundle ID: com.anonymous.FetchMart
          → produces an iosClientId

      (b) Application type: Android
          Package name: com.anonymous.FetchMart
          SHA-1 fingerprint: run this once you have a debug keystore:
            cd FetchMart/android && ./gradlew signingReport
          (the SHA-1 of the `debug` variant)
          → produces an androidClientId

      (c) Application type: Web application
          (No URIs needed — used internally by the Android SDK to mint idTokens)
          → produces a webClientId

    Where to put them — TWO places, one per side:

    BACKEND (used to verify incoming idTokens):
      market-backend/.env →
        GOOGLE_OAUTH_IOS_CLIENT_ID=xxxxx-yyy.apps.googleusercontent.com
        GOOGLE_OAUTH_ANDROID_CLIENT_ID=xxxxx-yyy.apps.googleusercontent.com
        GOOGLE_OAUTH_WEB_CLIENT_ID=xxxxx-yyy.apps.googleusercontent.com

    MOBILE (used to request idTokens from Google):
      FetchMart/.env →
        EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID=xxxxx-yyy.apps.googleusercontent.com
        EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID=xxxxx-yyy.apps.googleusercontent.com
        EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID=xxxxx-yyy.apps.googleusercontent.com

      FetchMart/app.json → under the `@react-native-google-signin/google-signin`
      plugin, replace YOUR_REVERSED_IOS_CLIENT_ID with your iOS client ID
      reversed. Example:
        iOS client ID:        123456-abc.apps.googleusercontent.com
        Reversed (URL scheme): com.googleusercontent.apps.123456-abc

[ ] APPLE SIGN-IN — Apple Developer setup
    Required for: "Continue with Apple" (iOS only).
    Cost: requires a paid Apple Developer account ($99/year).

    Step 1: Go to https://developer.apple.com/account/resources/identifiers
    Step 2: Find your App ID (or create one for `com.anonymous.FetchMart`)
    Step 3: Edit it and check "Sign In with Apple" capability → Save
    Step 4: Re-generate provisioning profiles if needed (Xcode usually auto-fixes)

    What you need to know:
      - The "audience" used to verify Apple's identity tokens IS the bundle ID.
      - There are no client secrets needed for the native iOS flow.

    Where to put it:
      market-backend/.env →
        APPLE_BUNDLE_ID=com.anonymous.FetchMart

    NOTE: Apple Sign-In does NOT work on Android natively. The button is
    automatically hidden on Android via `appleAuth.isAvailable()`.

[ ] DATABASE MIGRATION — OAuth schema
    Required for: storing OAuth provider links per user.

    Run from market-backend/:
      npx prisma migrate dev --name add_oauth_accounts

    What this does:
      - Makes users.password_hash nullable (OAuth-only users have no password)
      - Adds the `oauth_accounts` table with (provider, provider_uid) unique
      - Adds the AuthProvider enum (EMAIL / GOOGLE / APPLE)

    Then install new backend deps:
      cd market-backend && npm install

    Then install new mobile deps + rebuild native:
      cd FetchMart && npm install && npx expo prebuild --clean && npx expo run:ios
